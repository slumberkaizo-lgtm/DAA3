# Короткая подготовка к защите

## Что запустить

В PowerShell из папки проекта:

```powershell
.\gradlew.bat test
.\gradlew.bat demo
.\gradlew.bat run
```

Нужен JDK 17+. Если установлен только старый Java 8, укажи свой JDK:

```powershell
$env:JAVA_HOME='C:\Users\BG\.jdks\jdk-17.0.20.1+1'
.\gradlew.bat test
```

`demo` показывает маленькие понятные примеры. `run` запускает полный бенчмарк.

## Как объяснить за минуту

Один `Graph` хранит списки смежности и список рёбер. Для неориентированного
ребра в списках смежности есть оба направления, а в общем списке оно одно.
Поэтому Kruskal сортирует список рёбер, а обходы используют соседей вершины.

DSU хранит группы вершин. `find` находит корень и сжимает путь до него.
`union` присоединяет меньшую группу к большей. Это две отдельные оптимизации;
вместе они дают почти константную амортизированную стоимость.

Kruskal берёт рёбра по возрастанию веса и соединяет разные группы через DSU.
Prim растит дерево: берёт минимальное ребро из очереди и пропускает уже посещённую
вершину. Если граф распался на части, Prim начинает снова в другой части.
Оба возвращают лес минимального веса. Отрицательные рёбра им не мешают.

Kosaraju сначала сохраняет вершины по времени завершения обхода. Затем разворачивает
рёбра и идёт в обратном порядке завершения. Каждый новый обход даёт одну SCC.
Вместо рекурсии используются массивы как стеки, чтобы пережить путь из 100000 вершин.

Kahn добавляет в очередь вершины с нулевой входящей степенью. После удаления вершины
уменьшает степени её соседей. Если удалил меньше n вершин, в графе есть цикл.

Для кратчайших путей все источники получают расстояние 0. Остальные сначала имеют
бесконечность. Идём в топологическом порядке и обновляем расстояния соседей.
Отрицательный вес разрешён, поскольку в DAG нельзя вернуться назад по циклу.

## Вопросы, которые стоит потренировать

**Почему MST не получает цикл?** В Kruskal концы нового ребра находятся в разных
компонентах DSU. В Prim новое ребро ведёт в ещё не включённую вершину.

**Почему минимальное ребро безопасно?** Если его нет в оптимальном дереве, добавляем
его, получаем цикл и удаляем другое ребро через тот же разрез. Оно не легче нашего,
поэтому общий вес не увеличится.

**Почему один проход в DAG достаточен?** Все предшественники вершины уже обработаны
к моменту её обработки. Позднее ребро не сможет вернуться в неё.

**SCC и цикл — одно и то же?** SCC означает взаимную достижимость. Компонента из
нескольких вершин содержит цикл. Одиночная вершина циклична только при петле.

**Какие сложности?** Kruskal и наш ленивый Prim: O(V + E log(E+1)). Kosaraju, Kahn,
пути в DAG: O(V+E). DSU find/union: O(alpha(V)) амортизированно.

**Почему Prim не всегда O(E log V)?** Здесь очередь хранит рёбра, в том числе
параллельные, поэтому её размер может быть O(E). Для простого связного графа
log E = O(log V), но с параллельными рёбрами точнее писать log E.

**Как проверена правильность?** Два MST сравниваются на 100 случайных графах и с
полным перебором на маленьких. SCC сравниваются с взаимной достижимостью через BFS.
Пути в DAG сравниваются с Bellman-Ford, включая отрицательные веса.

**Почему нельзя доказывать сложность секундомером?** На время влияют JVM и нагрузка.
Счётчик обходов повторяем: Kosaraju = 2m, Kahn = m, релаксация DAG = m.
Построение обратного графа отдельно занимает O(V+E) и не входит в счётчик двух DFS.

**Почему при путях тоже вызывается Kahn, а счётчик только m?** Время включает оба
шага, но метрика строки DagShortestPath считает только релаксацию; у Kahn своя метрика.
Входящие степени хранятся в Graph, поэтому Kahn не пересчитывает их проходом по рёбрам.

**Что означает наклон 1 на log-log графике?** При росте размера в k раз счётчик
растёт примерно в k раз. Логарифмический множитель сортировки проверяем сравнением
весов, а не только числом рёбер, проверенных после сортировки.

**Что выбрать?** Для списка рёбер удобно Kruskal; для списка смежности — Prim.
Для порядка задач — Kahn; для групп взаимозависимых задач — Kosaraju.
Для кратчайших путей в DAG — топологический проход. В общем графе с положительными
весами — Dijkstra, с отрицательными — Bellman-Ford.

## Пример из demo

В `data/dag.txt` источники 0 и 1. До вершины 2 лучше идти из 1: стоимость 2.
Затем ребро 2 -> 3 имеет вес -5: расстояние до 3 равно -3.
Ребро 3 -> 5 имеет вес 2: расстояние до 5 равно -1.
Восстановленный путь: 1 -> 2 -> 3 -> 5. Итоговые расстояния: [0, 0, 2, -3, 3, -1].

В несвязном примере лес весит 8 и содержит 3 компоненты: {0,1,2}, {3,4}, {5}.
Петлю 2 -> 2 не берём, хотя её вес -10: она не соединяет разные вершины.
